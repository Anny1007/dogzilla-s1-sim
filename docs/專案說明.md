# DOGZILLA S1 自主避障 — 專案說明

給第一次接觸這個專案的人。依對象挑一段看就好。技術細節見 `sim_env/README.md`。

## 一句話

讓 12 個關節的小型機器狗 DOGZILLA S1 加裝 LiDAR 後，能自己建地圖、規劃路線、繞過障礙物走到指定地點。
目前已在電腦模擬裡把整套系統建好並測試過。

## 兩分鐘版

### 要解決什麼問題

機器狗原本只會照遙控指令走路，看不到障礙物。目標（`docs/project.pptx`）：

- 用新加裝的 LiDAR 偵測周圍的障礙物
- 自己走到目標點，途中繞過障礙物

### 系統怎麼運作

對應投影片的 Software Pipeline（`docs/architecture.svg`）：

1. **感知**：LiDAR 每秒掃描周圍 360° 的距離 10 次。
2. **建圖與定位（SLAM）**：一邊走一邊畫地圖，同時知道自己在地圖上的位置。
3. **路徑規劃（Nav2）**：在地圖上算出一條避開障礙物、通往目標的路線。
4. **避障控制**：沿路線前進，遇到障礙物時即時閃避。比較了兩種方法：
   - 傳統演算法（Nav2 的 DWB、RPP）
   - 強化學習（RL）：讓 AI 在模擬裡自己練習幾百萬次學會避障
5. **運動控制**：把「往前走、轉彎」的指令轉成 12 個關節的動作，讓機器狗用四條腿走路。

### 為什麼先做模擬

實機只有一台，舵機力氣小（每顆約 0.44 N·m），撞到或翻倒容易壞。所以先在 Gazebo 模擬器裡，
用 Yahboom 官方提供的 DOGZILLA S1 模型把整套流程跑通、調好參數，再搬到實機的樹莓派上。

### 目前成果

- 整條流程在模擬中一鍵啟動：在畫面上點一下目標，機器狗就會自己走過去。
- 投影片上的主要任務（從起點繞過障礙物走到右上角）已在模擬中完成，最終位置誤差約 4 公分。
- 連續走 7 個目標點的測試，實際到達率還不高（各方法 0–3/7），是下一階段要改善的地方。

## 技術細節版（給懂 ROS／機器人的人）

挑「遇到的問題 → 原因 → 解法」來講最能展現專案的深度：

| 問題 | 原因 | 解法 |
|---|---|---|
| 機器狗走路很晃 | 舵機力氣小、腿很輕，關節控制器在最大扭力兩端來回震盪 | 重調控制器並掃描步態參數，晃動降到原本的 1/4（RMS 7.0° → 1.8°） |
| 地圖上出現不存在的障礙物 | 四足走路時機身前後晃，LiDAR 掃到地面 | 依 IMU 傾角把打到地面的點濾掉 |
| 機器狗翻倒 | 路徑控制器下「快速前進加左右急轉」，超出這種步態能做到的範圍 | 加運動安全濾波：轉彎時自動降速、限制急轉 |
| 一啟動就趴下站不起來 | 控制器載入前腿是軟的，舵機力氣不夠撐起機身 | 以站姿生成，控制器就緒後才開始模擬 |
| 官方模型不能直接用 | 關節命名錯誤、旋轉軸方向不一致、左右質量不對稱 | 寫產生器自動修正，外觀、尺寸、質量保留官方數值 |
| Gazebo 一放機器狗就崩潰 | LiDAR 射線與網格碰撞模型的執行緒衝突（用 gdb 追到） | 碰撞形狀改用簡單方塊 |

地面點濾波和運動安全濾波在實機上一樣用得到。

## 目前的限制與下一步

- **走得慢**：S1 約 0.13 m/s，轉彎時更慢，大場地的長路段常在時間內走不完。
- **定位誤差會累積**：長時間運行後 SLAM 誤差可達 1 m 以上。
- **RL 在窄通道表現差**：需要針對窄通道再訓練。
- **尚未上實機**：模擬裡的速度、晃動、重量都需要在實機上重新量測（官方 URDF 的總重約 0.6 kg，可能沒算進舵機與電池）。

## 對外說明的建議

- **先展示，再解釋**：開模擬，在 RViz 點一個目標讓機器狗走過去。
- **數字要誠實**：主要任務做到了，但連續多點的到達率還偏低，原因是走得慢與定位誤差累積。
- **強調模擬的價值**：晃動、翻倒、看到地面等問題都在模擬裡先找到並解決，省下實機試錯的風險。
